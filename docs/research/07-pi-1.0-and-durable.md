# Pi 1.0 and Pi Durable: what changes for graph-agent

Checked against Pi at commit `319fecb` (2026-10-02, `@earendil-works/pi-*` 1.0.0)
and the 1.0.0 packages on npm. Sources: the [Pi 1.0](https://earendil.com/posts/pi-1-0/)
and [Pi Durable](https://earendil.com/posts/pi-durable/) announcements, the
package changelogs from 0.84.3 to 1.0.0, and `packages/durable/README.md`.

Two releases landed on 2026-10-01. **Pi 1.0** is the first stable release of
the agent toolkit we already depend on. **Pi Durable**
(`@earendil-works/pi-durable`) is a new, explicitly experimental package: a
durable agent harness in which every model call and tool call is committed to
storage before it is shown, so a dead process resumes where it stopped.

## 1. Upgrading 0.84.3 → 1.0.0 (#114)

A trial upgrade breaks exactly two files at compile time, plus two runtime
changes that the type checker does not catch.

| Change in Pi | Where | Effect on us |
|---|---|---|
| pi-agent-core 1.0 removed the experimental harness (tools, `NodeExecutionEnv`, the `./node` subpath) | `tool-executor.ts` | Compile error. The four tools now come from `@earendil-works/pi-coding-agent` as `createXTool(cwd)` |
| `shouldStopAfterTurn` removed (0.87) | `pi-session.ts` | Compile error, and ignored at runtime, so Pi would loop by itself. Use `finishTurn: () => ({ action: "end" })` |
| System prompt and tools became a leading `role: "system"` transcript message (0.86) | `harnesses.ts:392`, `compactHistory` | The "nothing to say" guard never fires, and compaction would drop the prompt and tool declarations |
| Tools return `isError: true` instead of throwing | `tool-executor.ts` | A failing `bash` would be reported as success unless the flag is forwarded |

The rest of 1.0 (codemode, MCP, virtual models, the fullscreen TUI, OAuth
logins) belongs to the Pi CLI, which graph-agent does not run.

## 2. Pi Durable, mapped onto graph-agent

Pi Durable and graph-agent solve overlapping problems from opposite ends.
Pi Durable makes *the conversation* durable and leaves control flow to code.
graph-agent makes *the control flow* a persisted BPMN graph and keeps the
conversation in memory.

| Pi Durable | graph-agent today |
|---|---|
| Atomic commits of entries, documents and tasks; nothing is shown before it is stored | Ordered writes (transcript, graph revision, engine state), but `session.jsonl` and `engine.json` are written once per pass |
| Every model and tool call is a checkpointed task | Activities are checkpointed only when the run parks or ends |
| A tool reruns after a crash only if it is `replay: "safe"`; otherwise the model gets `interrupted` | A recovered `agent:tool` would simply run again |
| `requestId` makes a retried submission idempotent | Answers are consumed once (#44, #51); steering and follow-ups are not deduplicated |
| An inbox of steers, follow-ups and writes | `inbox.jsonl`, drained by `agent:steer` and `agent:follow-up` |
| `watch()` and `viewState()` let several clients follow one conversation | The studio and the TUI's `--resume` reattach (#73) |
| `fork()` and task-owned subagent conversations | `callActivity`; no conversation forks |

While mapping these, one existing bug turned up: `resume` never reloads the
transcript, so the model on the far side of a gate starts from scratch and the
earlier history is overwritten on disk (#115).

### Adopt, or borrow?

**Borrow the ideas now; do not adopt the package yet.**

- Its README opens with *"Experimental. The API changes without notice between
  releases."* We already pin Pi exactly because minor releases break us.
- Adopting it would mean two durable state machines (its tasks and
  bpmn-engine's) owning the same tool calls. `pi.generation` runs the tool
  round itself and owns the `pi.tool` tasks. graph-agent's whole premise is
  that the graph decides whether each call happens, so we would have to fight
  its scheduler with `beforeTool` hooks.
- It brings `@earendil-works/chord` along for document state, which is a new
  dependency we have no other use for.

What carries over without the package:

- Commit the transcript and engine state after every activity (#116).
- Record a tool call's intent before running it, and never re-run a
  non-idempotent call silently on recovery (#117).
- Use transcript system messages to change the tool set mid-session (#118). This
  comes from pi-ai, not pi-durable, and is usable as soon as #114 lands.

Revisit adoption when pi-durable drops the experimental label. The likely seam
is its storage and `Conversation` (transcript plus inbox) under `PiSession`,
with the generation task's tool round replaced by parked tools as today.

## Order of work

#114 → #115 → #116 → #117 (land together with #116 or straight after), and #118 any time after #114.
